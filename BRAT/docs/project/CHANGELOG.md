- **Циклические `let` освобождают память; `brat build --mem N` вшивает бюджет в бинарник.** `_reclaim_names` раньше исключал привязки, объявленные внутри цикла: повторный `let` перезаписал бы неосвобождённое значение, поэтому `let line = ...` в цикле и `line = line + x` текли на каждой итерации (вариант B из шага 4 падал по лимиту 16 МиБ). Теперь анализ возвращает два множества: `reclaim` (перезапись через `set`) и `relet` (объявлено под циклом). Для `relet` эмиттер освобождает значение предыдущей итерации на самом `let` (RHS вычисляется первым, он может читать старое значение), переменные инициализируются `vnil()`, а `_share_root` считает ссылки и для них, поэтому значение, отданное в контейнер, переживает освобождение привязки. Арено-блоки помечены флагом в счётчике ссылок, поэтому лишний `vrc_dec` их не трогает. `--mem` принимает байты с суффиксом K/M/G и собирает бинарник с `BRAT_MEM_BYTES`: `main` ставит `RLIMIT_AS` до первого выделения, программа либо держит бюджет, либо падает громко. `emit-c --mem` вписывает `#define` в сгенерированный файл. Тесты: `test_loop_reclaim.py` (relet, чистый цикл-let, шаринг в контейнер; `RLIMIT_AS` 32 МиБ, вывод интерпретатора и C совпадает, мутация без освобождения падает по лимиту) и `test_mem_budget.py` (ограниченная программа проходит, растущая падает под бюджетом, без `--mem` бюджет не вшивается, мусорное значение отвергнуто; мутация без `-DBRAT_MEM_BYTES` роняет тест). Отказы правил выхода из арены теперь подсказывают выход: «if it must leave, hand out a heap copy: `own(...)`» (кроме захвата замыканием, где копия не советуется).

- **Арена, шаг 4: откат при Err и `own(x)`.** `own(x)` возвращает глубокую копию в куче, поэтому сообщение об ошибке переживает сброс арены: `return Err(own("bad {len(parts)}"))`. Правило выхода не заглядывает внутрь `own`. Аргументы тегов (`Ok`, `Err`), построенные внутри арены, переносятся в кучу в `vtagv`; без этого возвращённый `Err` указывал бы на освобождённую память (найдено AddressSanitizer). `emit-c --no-check` отказывает для программ с блоком `arena`. Тест `test_arena_request.py`: 3000 запросов, 600 с ошибкой; под лимитом 16 МиБ проходит только версия с ареной; AddressSanitizer чист. Мутация (старое поведение тегов) роняет тест.
  Старые проблемы, найденные по дороге, перечислены в docs/design/ARENA.md (раздел Known issues).

- **Арена, шаг 3: правила выхода значений из блока** (`typer.py`). Внутри блока `arena` значение считается выходящим наружу, если оно зависит от имени, объявленного в блоке, и его тип не скалярный. Отвергаются: возврат, присваивание внешней переменной, запись во внешний контейнер (индекс, поле, `push`), передача в пользовательскую функцию рядом с внешним именем, `spawn` и замыкание, захватывающие такое значение. Привязка, созданная из внешнего контейнера, считается псевдонимом и внутренней не считается. Арифметика и сравнения всегда скалярны. Ограничение из-за этого: вызов по пути, который не покрыт правилами, не отслеживается. Шлюз `BRAT_ARENA_UNCHECKED` удалён. Тест `test_arena_escape.py`: каждый отказ имеет свою программу и сообщение, принятые программы сравниваются между бэкендами. Мутация (отключённое правило возврата) роняет тест.

- **Арена, шаг 2: блок `arena { }`.** Парсер разворачивает его в существующие узлы: вход в арену, `defer` выхода и тело в собственном блоке. Поэтому выход из арены работает на всех путях, включая раскрутку ошибки, одинаково в интерпретаторе и в C. Векторы и словари внутри арены берут массивы из арены (`barr_new`, `barr_grow`), поэтому выход их возвращает. Вложенность: стек из 64 отметок. Найдена и исправлена ошибка: флаг арены обнулялся при приведении к `int`, что тихо отправляло контейнеры в `malloc`. Тесты: `test_arena_diff.py` (вывод обоих бэкендов совпадает, ошибка проходит через арену, лимит 16 МиБ на выделение доказывает освобождение, проверка флага). Мутация (выход без освобождения) даёт `out of memory` и падение теста.

  ошибку и не трогает чужой дескриптор. Интерпретатор работает по тем же правилам

- **Конкатенация строк в C-бэкенде не освобождает память, и рантайм не умеет
  освобождать вообще.** Механизма нет: ни рефокунта, ни `vfree` (`grep` по
  `crt.h` не находит ничего, кроме метода `del` у мапы). Сам `vadd` корректен
  — `malloc`, две `memcpy`, NUL — но возвращённая строка никогда не
  освобождается, поэтому `s = s + "x"` в цикле течёт. Замер: `n = 8000`
  потребляет ровно 8000²/2 = 32 МБ адресного пространства (порог совпадает до
  мегабайты), `n = 100 000` — около 5 ГБ. Именно это давало 172 секунды на
  бенчмарке строк и зависания машины: 5 ГБ на 3.7 ГБ RAM — это своп, а не
  вычисления. Интерпретатор этой болезни лишён (CPython сразу переиспользует
  промежуточную строку), то есть бэкенды расходятся не в скорости, а в том,
  завершается ли программа вообще. Не экзотика: сборка логов, рендер шаблона,
  сборка CSV — всё это попадает под удар.
- **`vraise` через `longjmp` неопределён при `-O2` — доказано тремя разными
  триггерами.** Все три сегфолтятся на `-O2` и работают на `-O0`: исчерпание
  лимита потоков в `spawn`, исчерпание памяти в конкатенации строк, и
  (починенный ранее) пустой тег `ok`. Чистейшее доказательство — один
  исходник, один `ulimit -v 32768`: `-O0` печатает `('err', 'out of memory')`,
  `-O2` сегфолтится. Падающая инструкция стабильна и сдвигается только при
  изменении несвязанного кода рядом — это подпись пути longjmp, а не любого
  вызывающего. Репа знала про эту форму (`b44d069` откатил C-часть фикса
  `$type` ровно потому, что `vraise` через longjmp ломает `-O2`), урок записали
  для одного места и не применили ко всему рантайму. **Это теперь первый по
  приоритету баг рантайма** — впереди утечки, потому что отказ памяти идёт
  *через* него: OOM, который должен давать честный `('err', 'out of memory')`,
  даёт сегфолт, и рантайм не может отчитаться о собственном ресурсном отказе.
- `vadd` (ветка строк): проверка результата `malloc` как в `bgrow`. На `-O0`
  отказ памяти теперь даёт `('err', 'out of memory')` вместо разыменования
  NULL. На `-O2` это по-прежнему маскируется longjmp-багом выше.

  `splice_file` с разным контрактом (имя модуля vs путь) - `import` внутри
  тела функции падал с FileNotFoundError; слил в одно. Удалены дубль
  `var_ref`, `_bodies`, `declare_all`, мертвые ветки в `ex_map_meth`,
  `_SV_SIMPLE["copy"]`, `isinstance`-фолбеки в `borrow.py`/`typer.py`,
  unreachable `raise` в `runtime.py`, `abort()` после `longjmp`.
- **Интерполяция выражений.** `"{expr}"` разворачивается парсером в цепочку
  `+`, поэтому внутри строк работает любое выражение: `{len(v)}`, `{p.x}`,
  `{n + 1}`, `{m.get(k)}`, `{s.upper()}`. Фигурные скобки, которые не
  содержат ровно одного выражения, остаются литералом - JSON-шаблоны работают
  без экранирования. Кавычка внутри placeholder'а с незакрытой скобкой не
  кончает строку, так что `{v.join("|")}` - один токен, а не три.
  Литеральный чанк - новый узел `rstr`, чтобы grow() не трогал его второй
  раз. Порты `bratp.brat` и `bratb.brat` получили то же самое, AST и
  диагностики совпадают. Пример: `lang/examples/interp.brat`, кейсы в
  `test_diff.py`.

- **Нативный i64 починен.** `long` в C 32-битный на Windows, поэтому каждое
  значение выше 2^31 резалось: `9223372036854775807` печаталось как `-1`,
  `time_ms()` тихо заворачивался. Значения теперь `int64_t` (`bint`), печать
  через `BINT_FMT`. Заодно: `vdiv`/`vmod` в общем пути считают floor и знак
  делителя как Python (был C-транкейт), `INT64_MIN / -1` не роняет процесс,
  `sum`/`parse_int` заворачиваются как интерпретатор, унарный минус на границе
  range тоже.
- **Regex: альтернация и группы.** Движок переписан в обоих бэкендах:
  интерпретатор — дерево с бэктрекингом, натив — симуляция множества состояний
  (Pike VM), поэтому `(a+)+b` не взрывается экспоненциально ни там, ни там.
  Поддержаны `( )`, `|`, `*` `+` `?`, классы, диапазоны, `\d \D \w \W
  \s \S \n \t \r`, `^`, `$`. Битая скобка — ошибка `bad regex pattern`
  в обоих бэкендах. `{n}` и POSIX-классы по-прежнему не поддерживаются.
- **Типизированные ключи map в нативе.** `{1: "a"}` и `{"1": "a"}` были одним и
  тем же ключом (ключи строковались): `m["1"]` находил значение int-ключа, а
  `k + 1` на int-ключе давал `"71"`. Ключи теперь `Val`, сравнение через `veq`,
  `keys()/items()/vals()` отдают ключи с типом.
- **Текстовые методы приведены к семантике Python:** `index_of` считает
  кодпоинты (байтовое смещение врало на любом не-ASCII), `lines()` — это
  `splitlines` (был split по пробелам), `join` рендерит элементы через тот же
  путь, что и `print` (`1-True-None-2.5`, было `1-1-0-0`), `sort/min/max`
  сравнивают контейнеры лексикографически (раньше всё было «равно»),
  `split("")` — ошибка, `parse_int`/`parse_float` строгие к `1_0` и hex.
- **Unicode case в нативе:** ASCII, Latin-1, Latin Ext-A/B, Greek (включая
  тоносные формы и финальную сигму), кириллица, `ß` -> `SS`. Было: `toupper`
  по байтам.
- **Печать и `str()` в нативе приведены к Python:** shortest round-trip для
  float (`0.3333333333333333`, было `0.33333333333333331`), `True/False`,
  `None`, repr внутри контейнеров (`['a']`, `('red',)`), было `?` для тегов.
- **Вложенные `fn` компилируются.** Было: `static` в блоке (C запрещает) плюс
  двойная эмиссия — любая программа с `fn` внутри функции не собиралась.
  Теперь вложенные функции эмитируются на верхнем уровне под mangled-именем,
  вызовы резолвятся через карцу имён, эмит двухпроходный (прототипы печатаются
  после того, как известен полный набор функций).
- **Телеметрия в нативе — валидный JSON:** экранирование кавычек и управляющих
  символов в `log.*`, кавычки вокруг строк в `trace.span`/`metric.*`
  (`["work"]`, было `[work]`), `metric.*` с 1 и N аргументами как в интерпретаторе.
- **Чекер: межфайловые сигнатуры не зависят от порядка аргументов.** `brat check
  a b` сливает pub-сигнатуры всех файлов, кроме проверяемого (раньше — только
  файлов после него, так что `modapp` работал по счастливой случайности алфавита).
- **`trace.span("x") { ... }`** — блочная форма из SPEC §8: десакарится в
  trailing-closure, строка спана печатается до работы, результат блока —
  значение выражения. Пример: `lang/examples/span.brat`.
- **Приоритет `||` ниже `&&`.** Оба были на одном уровне и лево-ассоциативны:
  `true || false && false` давал `false` вместо `true`. Пример:
  `lang/examples/precedence.brat`.
- **Экспоненциальная запись:** `1e10`, `1.5e-7`, `2E3` лексятся как числа
  (раньше — как `1` и identifier `e10`). Парсер и порт `bratp.brat` синхронны.
- **WAF как модуль на самом BRAT** (`balancer/examples/waf.brat`): правила —
  данные (map'ы), вердикты — значения (enum с payload), каждый хит шлёт
  `metric.counter` + `log.warn` через телеметрию языка. Никакого нового
  синтаксиса. Пример: `waftest.brat`, в обоих бэкендах побайтово равно.
- **Мёртвый код удалён:** `llvm_full.py` (1033 строки, ноль импортеров,
  `decl_runtime()` падал сразу), `vlog`, `vunwrap_ok`, `vname`, `map_del`
  по строке, дубли `var_ref`/`splice_file` в кодогене, `vcopy`-путь,
  `_bodies`, мертвые ветки в `borrow.py`/`typer.py`.
- **Постоянный дифф-сьют** `lang/tests/test_diff.py`: ~50 программ, каждая
  гоняется в интерпретаторе и в нативе, выход и код возврата сравниваются
  побайтово. Найденные им баги: все перечисленные выше.

- `map[K]V` настоящий: литерал `{"a": 1}`, чтение/запись `m[k]`, `v[i] = x`,
  методы `get/has/keys/del/set`, `for k in m`, паритет interp/native.
- Точечная запись в поля `p.x = v` в интерпретаторе (в C уже была).
- `assert(cond[, msg])` в C-бэкенде (раньше только интерпретатор).
- Рантайм-ошибки с номером строки: `RuntimeError: div by zero at line 3`.
- Mono fast-path: `fn f(x: i64) -> i64` с доказуемо целочисленным телом
  компилируется в сырой C `long` без боксов; не-int аргументы уходят
  в общий путь, семантика 1:1 с интерпретатором.
- `spawn` — настоящие потоки ОС + `join_all()` (снимок фреймов, первая
  ошибка пробрасывается, неявный join в конце программы).
- Оператор `in`: `x in vec`, `"k" in map`, `"sub" in str`.
- `or` выровнен со спекой: дефолт только для None (falsy-ловушки нет).
- Методы: `s.replace(a, b)`, `v.first()/last()` (None на пустом),
  `v.sort()` (in-place), `v.rev()`.
- Fast-path f64: `f64`-функции в сыром C `double` (int-деление внутри
  запрещено — расхождений с интерпретатором ноль).
- Чекер: Copy-семантика по аннотациям (`let x = n` на скаляре — копия,
  не заем), ложный `ref escapes` убран.
- Exhaustiveness в `match` (Rust-гарантия): непокрытый вариант енама —
  ошибка парсинга с именем варианта и строкой, `_` спасает.
- `typer.py`: статические острова типизации — аннотированные функции и
  топ-левел проверяются статически (`brat check` = borrow + typer),
  Rust-стайл ошибки со сниппетами; таблицы методов str/vec/map,
  элементы `vec[T]`, поля struct, арность вызовов.
- Настоящие потоки в C-бэкенде: `spawn` лифтится в замыкание,
  CreateThread/pthread, `setjmp`-раскрутка thread-local, ошибка потока
  долетает до `join_all`. Натив == интерпретатор на `spawn.brat`.
- Диспетч методов: пользовательские impl-методы всегда выше встроенных
  (vbuiltin fallback), коллизий имен нет конструктивно.
- Стдлиб: `index_of/repeat/split_once/chars/parse_float/copy` (str),
  `ins/del/slice/sum/min/max/enumerate/zip/chunks/copy` (vec),
  `items/vals/copy` (map).
- `x += e` и семейство (в т.ч. `v[i] +=`, `m[k] *=`), деструктуризация
  `let [a, b] = v`, дефолтные параметры `fn f(a: i64 = 5)`.
- `print` в fast-пути (i64/f64/str-интерполяция).
- Канал ошибок унифицирован: рантайм-ошибки (div0, OOB, no key) — значения
  `Err` в ОБОИХ бэкендах (`vraise` вместо 51 exit(1) в crt + эмиссии),
  ловятся через `try/catch` и в нативе; `catch e` наконец биндит payload.
- `try/catch` больше не глотает `return`/`break`/`continue` (return-unwind
  выделен в отдельный класс `Ret`) — починен реальный семантический баг.
- Match guards `Ok(v) if v > 0 =>`; голое имя в паттерне: lowercase —
  биндинг скрутини, Uppercase — вариант (как в Rust); залатан латентный
  баг вложенных списков в десахаре catch-all армов.
- Стбы-билтины балансировщика больше не перекрывают пользовательские функции.
- UTF-8 настоящий: `len/chars/s[i]/slice` по кодпоинтам в обоих бэкендах;
  починен `unicode_escape`-манглинг не-ASCII литералов в парсере;
  `_clit` эмитит UTF-8 байты. `s.slice(a, b)` для строк.
- Системные билтины: `args()` (argv в обоих бэкендах), `exit`, `eprint`,
  `raise(x)`, `time_ms`, `sleep_ms`, `env_get`, `re_match` (свой
  бэктрекинг regex-движок, одинаковый в interp и C).
- HoF: `fold/any/all/find/sort_by` + `pos`, `get_or`; работают и через
  точечный вызов (`v.fold(0, f)`), не только mcall-форму.
- `jsonlib.brat`: полный JSON-парсер на самом BRAT (рекурсивный спуск,
  Ok/Err), работает в обоих бэкендах.
- Fast-path `i64v`: `fn f(v: vec[i64]) -> i64` идет в сырой `Vec *` без
  боксов — чтение/запись элементов напрямую из `items` (с проверками),
  `for x in v` сырой. По мотивам gcshape/mono-collector: одна конкретная
  форма — одна специализация.
- Чекер: проекции-пути (checker v2, п.1): `move p.x` инвалидирует только
  `p.x`, sibling-поля живут (disjoint field moves как в Rust);
  `move cfg.net.host` vs `cfg.net.port` — независимы; индекс — `x.*`.
- Полная mut-дисциплина (как в Rust): присваивание только в `let mut` /
  `mut`-параметр (`assign to immutable` со строкой); Law of Exclusivity
  на call-site: mut-аргумент — mut-место без живых заемов и дублей;
  заемы изолированы по ветвям if/while/try/spawn. Весь сьют переведен
  на `let mut` где надо (2 дюжины файлов).
- Match: bool-паттерны `true`/`false` + закрытый домен (без `_` можно);
  `let mut [a, b]` деструктуризация; голые `mut x` параметры без аннотации.
- E0502/E0506: использование `x` при живом mut-займе — ошибка с двуспан
  заметкой; присваивание в `x` при любом живом займе — ошибка. Copy-pinning:
  `let mut i: i64 = 0` — аннотация фиксирует copy-тип, `let j = i` —
  копия, не заем (аннотированная арифметика copy не теряет).
- Правила spawn: `return` внутри — ошибка; запись в захваченную немутную
  переменную — ошибка (захват копией).
- Usefulness полный: вложенные варианты (`Has(Ok(v))`), енамы с одним
  вариантом — исчерпывающе без `_`; контрпримеры в сообщении.
- Стадия 4 часть 2: `bratp.brat` — полный парсер языка на самом BRAT,
  дифф-тест AST 62/62 побайтово с Python-парсером (`test_bratp.py`).
- Стадия 4 (самокомпиляция): `bratc.brat` — полный лексер языка на самом
  BRAT; дифф-тест 61/61 файла побайтово с Python-лексером (`test_bratc.py`).
- stdout/stderr интерпретатора — всегда UTF-8 (байты, как у Go/Rust).
- Фундаментальные фиксы: `&&`/`||` — настоящий short-circuit (в interp не
  было вообще; в codegen значения стерилизовались, но pre-statements RHS
  вычислялись безусловно); условие `while` с pre-statements теперь
  перевычисляется каждую итерацию (раньше замирало — висло).
- Чекер: unused-var warnings, двуспан диагностика (`note: x moved here`).
- Чистка: мертвый `to_c`-стаб и emit-c фолбек удалены, `skip_type`,
  мёртвая ветка ex_stub, fmt научился `+=`-семейству.
- Парсер: захват `-> i64`/`let x: i64` аннотаций (раньше выбрасывались);
  `match A { }` на голом конструкторе не путается со struct-литералом;
  многоуровневый field-set `a.b.c = v` в нативе (был молчаливый мусор).
- Диагностика Rust-стайла: чекер печатает `file:line: error: msg` +
  сниппет строки; синтаксические ошибки CLI — со сниппетом `--> file:line`.
- Чекер: `assign to const` теперь реально срабатывает (latent bug).
- `struct` literals `Point { x: 1 }` + field access, move-aware.
- `for i in 0..n` ranges, native `for` over vec, `break`/`continue`.
- `move x` + `fn f(s: move str)` signatures; `-> ref` rejected.
- UFCS methods: split/trim/upper/parse_int/join/push/pop.
- `defer` LIFO, `import` modules, duplicate `match` arms rejected.
