Killer features BRAT

Критерий отбора: фича усиливает то, что уже является идентичностью языка —
владение без GC, арены, побайтовое равенство интерпретатора и C, честные
измерения. «Киллер» здесь — то, чего нет у соседей по нише (Zig, C с аренами,
Rust), а не ещё один пункт в списке возможностей.

Сделано

1. **Вшитый контракт по памяти: `brat build --mem 16M`.**
   Бинарник получает RLIMIT_AS до первого выделения: программа либо держит
   бюджет, либо громко падает. У системных языков лимит памяти — это обвязка
   тестов (ulimit в CI) или внешний сторож (cgroup, OOM-killer). Здесь бюджет
   становится свойством самого артефакта: его нельзя «забыть включить» в
   проде, потому что он уже внутри. Вместе с аренами это замыкает историю
   «сервис на N запросов в 16 МиБ» из проверки тестами в гарантию, которую
   несёт бинарник. Тест: `lang/tests/test_mem_budget.py`.

2. **Подсказка `own(...)` в отказах арены.**
   Каждый отказ правила выхода (кроме захвата замыканием) теперь заканчивается
   на «if it must leave, hand out a heap copy: `own(...)`». Отказ без выхода —
   это стена; отказ с подсказкой — это обучение синтаксису в момент ошибки.
   rustc так делает для borrow-ошибок, и это половина его репутации. Тест:
   `test_arena_escape.py` требует подсказку в каждом отказе.

Дорожная карта (по убыванию ценности)

3. **`arena_stats()` — телеметрия арены изнутри программы.**
   Возвращает `{live, peak, resets}` для текущего блока. В C это реальные
   байты из `barena_alloc`; интерпретатор честно возвращает нули, как `time_ms`
   честно возвращает разное время — вывод бэкенд-зависим, поэтому дифф-тесты
   его просто не печатают. Киллер-эффект: программа сама себя сертифицирует —
   `if arena_stats().peak > BUDGET { raise ... }` внутри обработчика. Ни у
   одной аренной системы программа не может спросить «сколько я съела на этом
   запросе». Цена: счётчики в crt.h (~10 строк) + builtin в обоих бэкендах.

4. **`brat why <name>` — объяснитель владения.**
   Печатает рассуждение эмиттера о привязке: класс владения, членство в
   reclaim/relet, точки шаринга, точка освобождения. Данные уже существуют в
   `codegen_c.py` (`_reclaim_names`, `sym`, `_share_root`) — их нужно только
   показать. «Почему моя переменная не освобождается» — вопрос, на который
   сегодня отвечает только чтение 2500 строк кодгена. Инструмент, который
   показывает reasoning компилятора, — редкость даже у больших языков.

5. **`brat fuzz` — дифференциальный фаззер как подкоманда.**
   `test_fuzz.py` уже гоняет случайные программы; продуктовая версия добавляет
   минимизатор: падающая программа сжимается до минимального контрпримера
   автоматически (оба бэкенда детерминированы, поэтому бисекция по строкам
   сходится). Минимизатор — это то, что превращает «фаззер что-то нашёл» в
   «вот пять строк, которые ломают C-бэкенд».

Отвергнуто

- **REPL.** Не усиливает идентичность; интерпретатор уже быстрый для
  экспериментов через `run`.
- **LSP-сервер.** Преждевременно: язык меняется каждую сессию, протокол
  заморозил бы ошибки дизайна.
- **`brat run --mem`.** В интерпретаторе бюджет включал бы сам CPython
  (~20 МиБ базовых), поэтому маленькие лимиты были бы нечестными. Честная
  версия живёт только в нативном бинарнике.
