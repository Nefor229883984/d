# Рынок языков: почему языки умирают и что это значит для BRAT

> Подготовительный документ. Цель — не повторить типичные ошибки, из-за которых
> языки теряли аудиторию. Источники: публичные постмортемы, Wikipedia,
> статьи авторов (Walter Bright, Graydon Hoare, Rob Pike, Evan Czaplicki и др.),
> собственный LEDGER BRAT.

## 1. Паттерны смерти языков

### 1.1 «Слишком много всего» (D, C++, Scala)
- **Симптом**: язык пытается быть всем для всех. D поддерживает 5 парадигм,
  метапрограммирование через templates/CTFE/mixins, GC и manual memory.
- **Последствие**: кривая обучения крутая, инструментинг (IDE, отладчик) не поспевает,
  сообщество раскалывается на «подмножества».
- **Урок для BRAT**: BRAT уже выбрал узкую нишу (системный, ownership-lite, C-бэкенд).
  Не расширять парадигмы ради «полезности». SPEC §11 «что НЕ в v0.1» — держать.

### 1.2 «Нет экосистемы / инструментинга» (Nim, Crystal, V)
- **Симптом**: язык быстрый и приятный, но нет пакетного менеджера, LSP, CI-интеграции,
  отладчика. Пользователь уходит, потому что не может встроить в пайплайн.
- **Последствие**: «игрушечный» статус, даже при хорошем дизайне.
- **Урок для BRAT**: `brat pkg` (URL+sha256+vendor) — минимум. LSP/registry — roadmap,
  но честно признаны отсутствующими (LEDGER: «это инфраструктура, которой нет»).
  Не врать про экосистему.

### 1.3 «Обещали больше, чем дали» (V, Pony, Rust pre-1.0)
- **Симптом**: маркетинговые заявления («V компилирует за 0.1 с», «Pony безопасен»)
  не подтверждаются прогонами. Доверие теряется навсегда.
- **Урок для BRAT**: LEDGER и why.md уже делают обратное — честно перечисляют проигрыши
  (размер экосистемы, soundness, пропускная способность). Сохранять эту честность
  при любом изменении. Цифры — только из LEDGER.

### 1.4 «Сломали совместимость» (Python 2→3, Perl 6/Raku, Go 1.0→2 (не было))
- **Симптом**: крупный разрыв версий делит сообщество. Perl 6 стал отдельным языком (Raku).
- **Урок для BRAT**: «Editions нет, совместимость тестами» (LEDGER). Не вводить editions.
  Тесты — единственный контракт совместимости.

### 1.5 «Слишком умный типовой систем» (Haskell, Rust lifetimes, Scala implicits)
- **Симптом**: типовая система требует эксперта. Новичок не может написать рабочий код.
- **Урок для BRAT**: «Ноль аннотаций лайфтаймов» — осознанный выбор. Чекер внутрифункциональный
  и неполный, но честно признанный. Не добавлять сложность ради «soundness» без
  доказательства пользы.

### 1.6 «Зависимость от одного человека / компании» (CoffeeScript, Elm)
- **Симптом**: ключевой мейнтейнер уходит, проект стагнирует. Elm: Evan Czaplicki
  перестал отвечать на issues.
- **Урок для BRAT**: документация и тесты должны быть самодостаточны. Любой контрибьютор
  должен смочь продолжить по SPEC + LEDGER + тестам. Избегать «магии» в голове автора.

### 1.7 «Нет migration path с существующего стека» (D vs C++, Rust vs C)
- **Симптом**: нельзя постепенно перейти. Приходится переписывать всё.
- **Урок для BRAT**: C-бэкенд + ABI-совместимость (когда появится FFI) — путь миграции.
  Пока FFI нет (SPEC §9), честно признавать.

## 2. Типичные ошибки дизайна (анти-паттерны)

| Ошибка | Пример | Как избежать в BRAT |
|---|---|---|
| Скрытая сложность (deep modules) | Java I/O: 5 классов для чтения файла | Публичный API минимален: `run/check/build` в CLI |
| Несогласованность (одинаковые вещи по-разному) | JS `==` vs `===`, `null` vs `undefined` | Один `str`, один `i64`, один `?` |
| Магические дефолты | C++ implicit conversions | Явные преобразования, ошибки — значения |
| «Сахар» без семантики | CoffeeScript significant whitespace | Синтаксис = семантика, см. SPEC |
| Непроверяемые обещания | `unsafe` в Rust, `@trusted` в D | Нет `unsafe` вообще (парсер не знает слова) |
| Сломанный инструментинг | медленная компиляция Rust pre-2018 | Интерпретатор мгновенный; натив ~2 с |

## 3. Что делает язык живым (успешные примеры)

- **Go**: простота, быстрая компиляция, единый toolchain (`go fmt`, `go test`, `go build`).
  Урок: BRAT CLI (`run/check/build/pkg/test`) — единый вход, как Go.
- **Rust**: честность про soundness, Miri, CVE-трекинг, editions (но BRAT отказался от editions).
- **Zig**: простота, C-interop из коробки, comptime. Урок: BRAT должен дать FFI (roadmap).
- **Elixir**: документация и DX первичны. Урок: `docs/` и `guide/` — first-class.

## 4. Применимость к BRAT (чек-лист перед любой фичей)

1. Не нарушает ли это SPEC §11 (что НЕ в v0.1)?
2. Есть ли тест в `test_lang.py` / `test_native.py` / `test_diff.py`?
3. Оба бэкенда совпадают?
4. Обновлён ли LEDGER, если изменился статус?
5. Не добавлена ли абстракция «на будущее» без двух реальных use-case?
6. Не врём ли мы про возможности (экосистема, soundness, скорость)?
